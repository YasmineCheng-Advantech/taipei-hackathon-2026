# Traffic Gem

**把塞車捲起來，找到不塞的那 15 分鐘。**

### 👉 [打開網站](https://taipei-hackathon-2026-web.vercel.app)

手機開最適合。免註冊，大約 30 秒。

台北黑客松 2026 參賽作品｜議題 #4 內湖科技園區平日晨峰車流。作品名稱取自 traffic jam 的諧音。

---

## 通勤的人不缺交通資料，缺的是時間去讀懂它

市府已經公開了很多交通數據，但沒有人上班前會去看車速矩陣。

所以 Traffic Gem 是**結果導向**的：我們幫你讀完、算完，只給你一個答案——**幾點幾分經過哪個入口，就能避開塞車**。

## 怎麼用（30 秒）

| | 你做什麼 | 你拿到什麼 |
| --- | --- | --- |
| 1 | 選你從哪個入口進內湖、最晚幾點要到公司、時間能不能調整 | — |
| 2 | 如果有無法錯峰的原因（接送小孩、公司規定上班時間…）可以勾選，也可以自己填 | — |
| 3 | 按「產生今日推薦」 | **一個時間、一個入口。**例如「07:30 經過堤頂大道，路上少塞 3–4 分鐘」 |

**不同的人會拿到不同時段的建議**，避免大家照著同一個答案又擠在一起。建議當天固定，不會一直往後延。

我們建議的是「**經過入口的時間**」，不是「出門時間」——我們不知道你從哪裡出發。

## 推薦只是一半

你勾的「為什麼沒辦法錯峰」會被**匿名**記錄、彙整，變成交給市府的依據：

- 有多少人卡在接送小孩 → 學校提早到校照顧、幼兒園提早收托
- 有多少人被公司規定綁住 → 企業彈性上班誘因、錯開例行早會
- 有多少人沒有接駁可搭 → 加開早班接駁公車

每一條都附上負責局處。**我們不代表市府承諾任何事**，只是把資料整理成可以拿去談的東西。

## 交通分析在漢堡選單裡

熱力圖、錯峰情境、入口地圖、敏感度分析這些圖，我們**刻意**收進右上角的選單。因為民眾打開網站是想知道幾點出門，不是看圖表。

但資料一直都在：市府可以從這裡找出塞車的根本原因，民眾也能隨時查。

## 我們怎麼讓數字可以被檢查

這是一個黑客松作品，不是官方系統。所以我們把「哪些是真的、哪些是算的、哪些是假的」全部攤開：

| 做法 | 為什麼 |
| --- | --- |
| 每個數字都標示 **真實觀測／程式計算／情境假設／AI 生成** 其中一類 | 不讓人誤以為模擬數字是實測 |
| 模擬資料一律加**斜線紋路**，分享卡上會印「含模擬資料」 | 截圖轉傳時紋路可能被忽略，所以再加文字 |
| 沒有偵測器的入口**留白，不補數字** | 麥帥二橋、康寧路三段目前沒有資料，我們就空著 |
| 不預測「全市會改善幾 %」，只反推「尖峰要移出多少比例才有效」，而且用**區間** | 單一數字會被當成保證 |
| 人數（意向登記、「我也需要」）**沒有後端就顯示「尚無資料」**，絕不放模擬值 | 假的人數看起來像民意，這條線不能跨 |
| 我們自己列出「可能錯在哪」 | 區間這麼寬，是因為結論最受「尖峰有多高」和「道路容量」影響 |

## 資料從哪裡來

- **真實資料：** 臺北市交通管制工程處 VD 車輛偵測器（`VDLive.xml`、TDX 歷史資料），2026-09-23～10-22 的平日 07:00–10:30。8 個入口裡有 5 個有真實資料。
- **即時路況：** 每 5 分鐘向交工處取一次現在的車速，只回答「現在多塞」，**不參與推薦、不改任何結論數字**。取不到時只有那一列顯示「暫時取不到」，其他照常。
- **模擬資料：** 沒有偵測器的入口、排隊模型的輸出，畫面上都有標示。

完整清單（含每一筆的授權與用途，以及用到的 AI 工具與開源套件）：**[`data/SOURCES.md`](data/SOURCES.md)**

## 你的資料我們不收

- 設定（入口、時間、彈性）**只存在你自己的瀏覽器**，不上傳。
- 後端只會存：日期、入口、時段、一組匿名裝置代碼。**不記 IP、不收任何個資。**
- 詳細說明：[`SECURITY.md`](SECURITY.md)

## 想自己跑跑看

零相依套件，需要 Node 18+：

```bash
cd web
node build.mjs                      # 打包成單一個 dist/index.html
node src/screens.test.mjs           # 22 個畫面的自動檢查
cd dist && python3 -m http.server 4321
```

網址可以加 `?topic=<id>` 換題目看，例如 [`?topic=b1-1999-mock`](https://taipei-hackathon-2026-web.vercel.app/?topic=b1-1999-mock)（1999 陳情，模擬資料）。**網站只讀一份題目 JSON，換題不改程式。**

整個網站是**單一 HTML 檔**：字型內嵌、地圖是 SVG 示意圖、沒有任何外部請求，所以離線也能完整操作。

| 路徑 | 內容 |
| --- | --- |
| [`web/`](web/) | 網站原始碼：22 個畫面、資料層、迷你執行層、打包腳本、即時 VD 代理 |
| [`data/schema/`](data/schema/) | 資料契約與驗證腳本——每個數字都要有來源標示，少一個就不給過 |
| [`data/processed/`](data/processed/) | 真實 VD 的彙整與處理腳本 |
| [`data/mock/`](data/mock/) | 三份模擬題目與產生腳本（結果固定、可重跑） |
| [`data/fetch/`](data/fetch/) | 資料收集腳本 |
