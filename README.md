# Traffic Gem

台北黑客松 2026 參賽作品。**一個手機優先的網站：先用熱力圖指出問題在哪裡、什麼時候發生，再給民眾一個今天就能照做的具體建議，並把大家的選擇與回報彙整成給市府的證據與行動清單。**

不只做熱力圖。熱力圖只回答「哪裡有問題」，我們還要回答「我該怎麼做」「如果大家都這樣會怎樣」「個人做不到的部分，誰該做什麼」（見下面的[產品結構](#產品結構)）。這個結構不綁定題目，換題時只換資料與文字。

- **最完整的版本：** 推測題目 #4，內湖科技園區平日晨峰車流。熱力儀表板呈現每 15 分鐘湧入內湖的車流熱點，告訴通勤的人今天幾點經過入口最好，再算出錯峰效果，並做一頁給市府與企業協商彈性工時用的文件。
- **換題準備：** 題目變成車禍／交通安全、公車／大眾運輸設點時的做法，見 [`docs/topics/`](docs/topics/README.md)。

作品名稱用「總名稱｜題目副標」：總名稱 Traffic Gem 不變，副標隨題目換（目前是「內科晨峰」，同首頁設計稿 [`design/landing/`](design/landing/)）。原本的「內科交通政策實驗室」只適用 #4，不再使用。

> 目前為賽前準備階段。主辦方 10/24 才公布題目，#4 只是推測。

## 產品結構

每個題目都依同一個結構設計：

1. **熱力圖**：問題在哪裡、什麼時候發生。
2. **幫你決定**：給民眾一個具體建議（幾點經過塞車路段、走哪條路、停哪裡），建議當天固定，不會一直往後延。
3. **如果大家都這樣**：處理所有人都照建議做時的集體效應，例如時段認領名額、分散推薦、容量檢核。
4. **城市行動**：把民眾的認領與回報彙總成給市府的證據，附負責局處；並提供給市府與企業的協商一頁紙。

## 資料標示

畫面上的每張圖、每個數字都標示以下其中一類：

- 真實觀測
- 程式計算
- 情境假設
- AI 生成

模擬資料一律加斜線紋路。設計範本中的數字**全部為模擬資料**；目前已有的真實資料是臺北市 VD（10/19–10/23 平日收集，見 [`data/processed/`](data/processed/README.md)）與 114 年傷亡事故逐案資料（只彙整到路口，見 [`docs/topics/crash.md`](docs/topics/crash.md#1023-用-114-年真實資料看到的)）。
