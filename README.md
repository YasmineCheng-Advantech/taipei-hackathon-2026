# Traffic Gem

台北黑客松 2026 參賽作品。**一個手機優先的網站：先用熱力圖指出問題在哪裡、什麼時候發生，再給民眾一個今天就能照做的具體建議，並把大家的選擇與回報彙整成給市府的證據與行動清單。**

不只做熱力圖。熱力圖只回答「哪裡有問題」，我們還要回答「我該怎麼做」「如果大家都這樣會怎樣」「個人做不到的部分，誰該做什麼」（見下面的[產品結構](#產品結構)）。這個結構不綁定題目，換題時只換資料與文字。

- **最完整的版本：** 推測題目 #4，內湖科技園區平日晨峰車流。熱力儀表板呈現每 15 分鐘湧入內湖的車流熱點，告訴通勤的人今天幾點經過入口最好，再算出錯峰效果，並做一頁給市府與企業協商彈性工時用的文件。
- **換題準備：** 題目變成車禍／交通安全、公車／大眾運輸設點時的做法，見 [`docs/topics/`](docs/topics/README.md)。

作品名稱用「總名稱｜題目副標」：總名稱 Traffic Gem（10/23 確定）不變，副標隨題目換（目前是「內科晨峰」，同首頁設計稿 [`design/landing/`](design/landing/)）。原本的「內科交通政策實驗室」只適用 #4，不再使用。

> 目前為賽前準備階段。主辦方 10/24 才公布題目，#4 只是推測。

## 產品結構

每個題目都依同一個結構設計：

1. **熱力圖**：問題在哪裡、什麼時候發生。
2. **幫你決定**：給民眾一個具體建議（幾點經過塞車路段、走哪條路、停哪裡），建議當天固定，不會一直往後延。
3. **如果大家都這樣**：處理所有人都照建議做時的集體效應，例如時段認領名額、分散推薦、容量檢核。
4. **城市行動**：把民眾的認領與回報彙總成給市府的證據，附負責局處；並提供給市府與企業的協商一頁紙。

## 資料標示

畫面上的每張圖、每個數字都標示以下其中一類：

- 真實觀測
- 程式計算
- 情境假設
- AI 生成

模擬資料一律加斜線紋路。設計範本中的數字**全部為模擬資料**；目前已有的真實資料是臺北市 VD（10/19–10/23 平日收集，見 [`data/processed/`](data/processed/README.md)）與 114 年傷亡事故逐案資料（只彙整到路口，見 [`docs/topics/crash.md`](docs/topics/crash.md#1023-用-114-年真實資料看到的)）。

### Demo 操作說明

手機優先，桌機用瀏覽器的手機模式（390px 寬）看最接近實機。打開網址後：

底部固定三個分頁：**今日／數據／設定**；右上角的按鈕打開**選單**，給市府與企業的七張圖都在那裡。

| # | 做什麼 | 看到什麼 |
| --- | --- | --- |
| 1 | 首頁按「**準備出門**」 | 進入設定：選常走的入口、最晚幾點要到、能不能調整時間、為什麼不能調 |
| 2 | 回到分頁「**今日**」 | 今天建議幾點經過該入口、會早到幾分鐘；划不來時會直接說「照平常時間走就好」 |
| 3 | 右上角開「**選單**」→「**熱力圖**」 | 8 個入口 × 每 15 分鐘的車速與流量。**斜線紋路＝模擬資料**；留白＝那個入口沒有偵測器，我們不補數字 |
| 4 | 點任一格 | 該格的平均／最低／最高車速、幾天裡有幾天低於 20 km/h、是真實觀測還是模擬 |
| 5 | 選單 →「**錯峰情境**」 | 要讓排隊減半，尖峰要移出多少比例的車（區間呈現） |
| 6 | 選單 →「**哪個假設最影響結論**」 | 敏感度分析：結論最受「尖峰有多高」與「道路容量」影響 |
| 7 | 選單 →「**我們可能錯在哪**」 | 我們自己列出的限制與不確定性 |
| 8 | 分頁「**數據**」 | 給市府與企業的行動清單、附負責局處，以及資料從哪裡來 |
| 9 | 今日頁往下 →「**分享**」 | 產生 1200×630 的分享卡，用到模擬數字時會印「含模擬資料」 |

選單裡另有「入口地圖」「哪個入口最塞」「排隊是怎麼來的」三張圖。

**換題目看：** 網址加 `?topic=<id>`，例如 [`?topic=b1-1999-mock`](https://yasminecheng-advantech.github.io/taipei-hackathon-2026/?topic=b1-1999-mock)（1999 陳情，模擬資料）、`?topic=a1-evening-mock`（晚尖峰，模擬資料）。網站只讀題目 JSON，換題不改程式。

**離線也能跑：** 整個網站是單一 HTML 檔，字型內嵌、地圖是 SVG 示意圖，沒有任何自動載入的外部資源。

### 目前這個網址的已知限制

GitHub Pages 是純靜態，跑不了 [`web/api/live.js`](web/api/live.js)（即時路況的 Serverless Function），所以**「現在路況」那一列會顯示「暫時取不到即時資料」**，其他 18 個畫面完全正常——前端對後端失敗的處理就是只讓那一列降級，不會整頁壞掉。要有即時層就另外部署到 Vercel（設定已在 [`web/vercel.json`](web/vercel.json)）。

推上 `master` 會自動重建並更新這個網址（[`.github/workflows/deploy-pages.yml`](.github/workflows/deploy-pages.yml)），網址不會變。
