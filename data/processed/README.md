## 資料來源現況（重要）

- **data.gov.tw 166031 已下架。** 頁面標示「資料集已下架，此為歷史資料留存」，詮釋資料最後更新 2024-09-11，提供機關寫的是地政司，原本就是指向 TDX 的轉載。ROLES.md／TASKS.md 寫的收集來源要改。
- **臺北市交工處 VD（可用，免金鑰）**，就是之後收集程式該抓的來源：
  - 靜態：`https://tcgbusfs.blob.core.windows.net/blobtisv/VD.xml`（data.taipei「臺北市車輛偵測器(VD)靜態資料」，604 支，交通部即時路況標準 v2.0）
  - 即時：`https://tcgbusfs.blob.core.windows.net/blobtisv/VDLive.xml`（約 1.7 MB，每分鐘更新，數值為 5 分鐘統計；分車種 M 機車／S 小車／L 大車／T 聯結車，分車道）
  - 另有舊格式 `GetVDDATA.xml.gz`（逐車道）與 `GetVD.xml.gz`（路段彙總，附路段名如「環東進城 前方」，對照位置很好用）。
- **TDX**：連得到，但 API 回 401「Valid API Key Required」，沒有金鑰不能用。國道 VD 只能從這裡（或高公局）拿。
- **高公局 tisvcloud.freeway.gov.tw**：從這個雲端環境連線逾時（伺服器端沒回應，不是網域白名單問題，推測只開放國內 IP）。在你自己的電腦上應該抓得到。
- **地圖服務（OSM／Nominatim）** 被網路政策擋住，所以位置對應是用 VD 座標、道路名、LinkID 方向和 `GetVD` 的路段名比對，沒有疊地圖確認。

## 每個入口怎麼對應

- **內湖路一段**：取最西端的東向 VD（路段名「內湖路一段文湖路至91巷(往東)」），3 個車道全偵測。往東還有 VTNR640、VTHRR20 可備用。
- **堤頂大道北向**：VPMSV40 在民權東路–舊宗路之間，北向 4 車道全偵測，是 Demo 故事裡的瓶頸段。下游 VRPSV00（舊宗路–港墘路）、VRHT600（港墘路，6 車道）可交叉驗證。
- **民權大橋**：橋上沒有 VD。VQBUL20 在民權東路六段、堤頂大道路口以東，東向 4 車道。會多算到從堤頂大道轉進來的車，也可能少算往堤頂轉走的車。
- **麥帥二橋**：VD 清單裡名字叫「麥帥二橋」的只有 V7230E0，偵測方向是南向（路段名「麥二正氣」，往基隆路／正氣橋），也就是離開內湖。往內湖方向沒有偵測器，跟設計稿標的缺口一致。
- **成美橋**：橋上沒有 VD。VMLXB00 在向陽路（重陽路–新明路）南岸引道，北向 3 車道全偵測，算是橋的上游入口。
- **環東大道**：設計稿把它放在東側、標「往內科」，所以我取東端由國3／南港往西進來的「環東進城 前方」V6310G0（3 車道）。**如果你指的是西端從基隆路經麥帥一橋進內湖的那股車流**，請改用 V6120C0（環東出城，2 車道）；下內科的匝道另有 V6140C0（堤頂舊宗）、V6151C0（舊宗匝道）。
- **國1 內湖交流道**：國道偵測器不屬臺北市，要等 TDX 金鑰，先標「待 TDX」。
- **康寧路三段**：臺北市 604 支 VD 裡沒有任何一支在康寧路。最近的 VSHZU60 在成功路五段，是另一條路，不建議代用。

## 機車涵蓋

- 臺北市 VD 有分車種，機車是 `VehicleType=M`。表上「是」代表該 VD 在抽樣的 3 次裡實際測到機車，而且偵測車道數等於實際車道數（沒有漏測車道）。
- 這些 VD 的車道類型都標 1（一般車道），沒有獨立的機車道偵測，機車是混在一般車道裡計數。
- 環東大道與國道禁行機車，標「不適用」。

## 缺口建議補法

- **麥帥二橋、康寧路三段**：熱力圖用模擬資料加斜線（schema 的 `gap`），說明文字註明「無偵測器，數值為推估」；如果主辦方有交工處路口調查，可以拿來校準尖峰量。
- **國1 內湖交流道**：TDX 金鑰下來後，用 `Road/Traffic/VD/Freeway` 找內湖交流道的匝道 VD；在那之前維持模擬。
- **民權大橋、成美橋**：資料是真的，但位置是引道，畫面上可以加一個小註記「偵測點位於引道」。

## 檔案

- `entrances.csv`：工項 4 規定的 6 個欄位（入口, 方向, VD編號, 是否涵蓋機車, 缺口標記, 資料來源）。
- `entrances_detail.csv`：每個入口的 LinkID、座標、偵測方向、偵測車道數、3 次即時抽樣結果、對應依據與信心。
- `build_vd_15min.py`：把收集程式的讀數（`vd_taipei_targets.csv`）彙整成熱力圖的 15 分鐘格子，輸出 `vd_15min.json`：每支偵測器 × 每格的多天平均、最小、最大、天數、低於 20 km/h 的天數。只用狀態正常的讀數，同一筆不重複計算，車速依車輛數加權。接著用 `gen_t4_morning.py --real` 產生正式資料檔，見 `data/mock/README.md`。
- `preview_vd.py`：收集期間隨時可以跑的預覽。讀 `data/raw/vd_taipei_targets.csv`，產生 `data/raw/preview.html`（含真實資料，不進 git），用瀏覽器打開就能看熱力圖、各入口車速折線、車種比例與最新讀數，不需要網路。
- `explore_vd.py`：探索用的圖表（找靈感，不是作品畫面），產生 `data/raw/explore.html`。11 張圖分成什麼時候塞、哪裡最塞、早一點經過有差嗎、每天都一樣嗎、都是什麼車、塞住的時候路能放多少車，每張圖下附一句從資料算出的結論。第 11 張的放行量可以拿來校正排隊模型的容量假設。
- `build_entrances.py`：重跑腳本。先下載 `VD.xml` 與 `VDLive.xml`，再執行 `python3 data/processed/build_entrances.py <下載資料夾> data/processed VDLive.xml [更多 VDLive 檔]`。
