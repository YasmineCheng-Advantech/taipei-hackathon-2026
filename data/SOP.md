# 換題 SOP（資料）

10/24 公布題目後，資料這邊照這份做。目標：**T0 + 1 小時交第一份模擬 JSON，T0 + 2 小時換上能取得的真實資料**（T0 是題目公布的時間，時程同 [`ROLES.md`](../ROLES.md#進度確認)）。

## 先決定從哪一份改

三份產生腳本都在 `data/mock/`，挑最像新題目的那一份複製來改，不要從零開始：

| 新題目長這樣 | 從這份改 | 例子 |
| --- | --- | --- |
| 地點 × 一天裡的時段，有「幾點經過／出發」的建議 | `gen_t4_morning.py` | 晨峰、晚峰、文湖線擁擠、停車場幾點有位 |
| 同一個題目換時段或方向 | `gen_a1_evening.py`（讀 t4 的結果再改） | 晚尖峰、假日 |
| 地點 × 類別或月份，沒有「幾點」 | `gen_b1_1999.py` | 1999 陳情、病媒、行道樹、淹水、吸菸熱點 |

## 步驟

### 0. 選題（T0 → T0 + 30 分）

照 [`HANDOVER.md`](../HANDOVER.md#賽前準備清單) 的選題規則。資料這邊要回答的只有一題：**這題有沒有能直接下載的資料？** 查 [`catalog.md`](catalog.md)，在群組裡回報「有／沒有／只有模擬」。

### 1. 第一份模擬 JSON（T0 + 30 分 → T0 + 1 小時）

1. `cp data/mock/gen_<最像的>.py data/mock/gen_<新題 id>.py`，題目 id 用小寫英數與連字號，例如 `c1-parking`。
2. 依序改這幾樣，其他先不動：
   - `meta`：`id`、`title`、`subtitle`、`region`、`sources`、`mock_method`（寫明數字怎麼來的）。
   - 熱力圖的列（地點）與欄（時段或類別）、圖層的名稱、單位、門檻。
   - `decide` 的 `title`、`metric`，以及選項是什麼（時間、管道、地點）。
   - `city.actions`：每項的局處、為什麼、對你的好處。
3. 跑腳本，再跑驗證：
   ```
   python3 data/mock/gen_<新題 id>.py
   python3 data/schema/validate.py data/mock/<新題 id>.json
   ```
4. 通過就 commit、push，跟網站工程師說「`?topic=<新題 id>` 可以接了」。**不要等數字完美**，網站先接得上最重要。

### 2. 換上真實資料（T0 + 1 小時 → T0 + 2 小時）

1. 從 `catalog.md` 找資料，下載到 `data/raw/<題目 id>/`（不進 git）。
2. 整理成「地點 id、時間（或類別）、值」三欄，放 `data/processed/`。VD 類可以直接用 `build_vd_15min.py`。
3. 在產生腳本裡把有真實資料的格子換掉：`label` 照實標，`sim: false`，`src` 指到 `meta.sources` 的 id。做法照 `gen_t4_morning.py --real`。
4. 再驗證一次、push、通知網站。

### 3. 交件前（交件前 1 小時起）

- 更新 [`SOURCES.md`](SOURCES.md)：新題用到的真實資料與模擬資料。
- 跟設計確認：簡報裡的數字和 JSON 一致。

## 容易出錯的地方

這些是 10/20 做 a1、b1 演練時踩到的，細節見 [`data/mock/README.md`](mock/README.md#演練找到的契約問題待網站工程師確認)。

- **每個數字都要有 `label` 和 `sim`。** 驗證腳本會擋；缺了網站會顯示錯誤。
- **人數一律 `pending`。** 意向登記、「我也需要」這類人數不能放模擬值，驗證腳本會擋。
- **`meta.sim: true` 時，檔案裡不能有任何 `sim: false`。** 混了真實資料，`meta.sim` 要改成 `false`。
- **非時段的題目：** `meta.time_range` 和 `bin_minutes` 還是必填，先填 `00:00`–`23:59` 與 `1440`（提案改成選填）。
- **情境不是一天裡的時段時：** `clear_time` 只能寫時刻，填 `null` 會被當成「不排隊」。先另外放 `clear_col`（提案中）。
- **非交通題也要有 8 個區塊。** 用不到的區塊放最小內容，例如 b1 的情境改成「積案」而不是「排隊」，一樣用排隊模型。
- **陳情原文不能進 repo。** 主辦方的陳情資料只放彙總統計。
