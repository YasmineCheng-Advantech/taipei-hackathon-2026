# Traffic Gem 定位一頁紙

Oct 23, 2026 · **草稿，待三人同意**（[`ROLES.md`](../ROLES.md#設計) 設計 P0 第 1 項）。內容整理自 [`README.md`](../README.md)、[`PRODUCT.md`](../PRODUCT.md)、[`traffic-gem-visual.html`](traffic-gem-visual.html)（視覺指南）與 [`landing/`](landing/README.md)（首頁改稿）。標「待決定」的地方要全隊決定。

## 作品名稱

- **總名稱：Traffic Gem**（10/23 全隊確定）。
- **題目副標：** 隨題目換，目前是「Traffic Gem｜內科晨峰」。換題時只換副標，例如「Traffic Gem｜路口安全」。
- **名字的故事：** traffic jam 是塞車，jam 也是果醬；把塞住的車流捲開，找到的不塞時段就是寶石（gem）。Demo 開場一句話：「我們把 traffic jam，變成 traffic gem。」
- **中文名：交通捲**（10/23 確定）。用「捲」不用「卷」，「卷」容易看錯成「券」。
- **原本的「內科交通政策實驗室」只適用 #4，不再使用。**

## 一句話定位

**一個手機優先的網站：先用熱力圖指出問題在哪裡、什麼時候發生，再給民眾一個今天就能照做的具體建議，並把大家的選擇與回報彙整成給市府的證據與行動清單。**

不只做熱力圖。每個題目都是同樣的四層：熱力圖（哪裡、什麼時候）→ 幫你決定（我該怎麼做）→ 如果大家都這樣（集體會怎樣）→ 城市行動（個人做不到的，誰該做什麼）。

**標語：**

| 標語 | 用在哪 |
| --- | --- |
| 把塞車捲起來 | 主標語：封面、網站頁首、Demo 開場 |
| From traffic jam to traffic gem | 英文副標 |
| 錯開 15 分鐘，路就鬆了 | 「幫你決定」頁、分享卡底部 |
| 一起分著吃，才夠大家吃 | 講為什麼要分開走 |
| 今天，你要哪一片？ | 拉票，引導打開網址 |

標語都是塞車題的。換成車禍、公車設點等題目時，只留「Traffic Gem」與英文副標，其餘照題目重寫。

## 讀者

| 讀者 | 看什麼 | 要做到 |
| --- | --- | --- |
| **主要：投票的一般民眾** | 大眾版（手機）：今天、大家一起、分享卡 | 打開網址 30 秒內知道「這跟我有關、我可以做什麼」，願意分享 |
| **次要：市府與企業** | 專業版（桌機）：熱力儀表板、錯峰情境、協商一頁紙、我們可能錯在哪 | 相信數字、拿得去用 |

Demo 順序照 [`PRODUCT.md`](../PRODUCT.md#兩分鐘-demo-怎麼講)：熱力圖 → 錯峰情境 → 協商一頁紙，民眾版只占約 20 秒；民眾版的任務是讓網址自己拉票。

## 想帶給讀者的感受

| 感受 | 怎麼做到 |
| --- | --- |
| **可信** | 每個數字都標來源；沒有資料就說沒有，沒有偵測器的地方留白，不補數字。這份誠實是作品最大的個性 |
| **冷靜** | 塞車已經讓人煩了，畫面不再加壓，不誇大效果；結果一律用區間 |
| **有行動力** | 重點是「我可以怎麼做」，不是「哪裡很慘」 |
| 看得懂（輔助） | 國小、國中程度的人看 5 秒就知道幾點最塞、自己該幾點走 |
| 帶點輕鬆（輔助） | 公開票選靠分享，名字的諧音讓分享卡想被轉傳；輕鬆只用在品牌外層 |

**要避免：** 像競選文宣、恐嚇（「死亡路口」這類標籤）、誇大效果，也不要把通勤的辛苦講得太輕佻。

## 語氣規則

1. 用一般人聽得懂的話。民眾畫面全面改用 [`plain-copy.md`](plain-copy.md) 的白話對照表（10/23 確定）；給市府與企業的畫面維持專業用語。
2. 數字一定附標籤：真實觀測／程式計算／情境假設／AI 生成；模擬資料加斜線紋路，寫「示範數字，不是真的」。
3. 不用「保證」「解決」「最危險」這類字眼；個人建議的分鐘數一律給區間，並同時寫出會早到幾分鐘。
4. 不用模擬人數當民意：人數只放真實登記，標「意向登記，未經驗證」；沒有資料就寫「還沒有資料」。
5. 城市行動註明「作品依資料提出的建議，不代表市府承諾」。
6. 一句話不超過 15 個字（民眾畫面）；拿生活裡的東西來比（時鐘、慢跑、看電影）。

## 和主辦方政見的距離（10/23 確定）

主辦方是沈伯洋競選辦公室，前三名經同意後會刊登在其競選官網。內湖相關政見（以誘因讓企業彈性工時、錯峰、幼托延托、捷運最後一哩路）和 #4 高度重疊（見 [`HANDOVER.md`](../HANDOVER.md)）。

**保持距離，讓資料說話。**

- 畫面與簡報不提候選人名字、不引用政見、不用競選的顏色或口號。
- 結論剛好和政見重疊時（例如彈性上班要搭配幼托），照資料呈現，並寫出算法與「我們可能錯在哪」；不說「證明政見正確」。
- 城市行動同時列出需要跨機關協調的項目（新北市、高公局），不把責任全推給市府。
- 理由：投票的是一般民眾，作品看起來像文宣反而扣分；保持中立，數字才可信。

## 視覺方向（10/23 確定：3D 瑞士捲）

**用這張 3D 瑞士捲：** [`landing/swiss-roll-proposal.webp`](landing/swiss-roll-proposal.webp)。橘色瑞士捲流出果醬，玩具車卡在果醬裡。

它是兩個版本合在一起：**主題**用視覺指南的瑞士捲與果醬，**畫法和顏色**用首頁改稿的 3D 玩具車（霧面、縫線、膨膨的黏土質感）。視覺指南裡莓果醬紅 `#8A2414` 的配色不用。

| 項目 | 用什麼 |
| --- | --- |
| 主視覺 | 3D 瑞士捲 ＋ 玩具車，蜜桃色漸層背景 |
| 字標 | 「Traffic Gem」圓胖字，同首頁改稿（Grandstander 800），橘色 `#D9522A` |
| 品牌色 | 橘色代表塞車：只用在插畫、字標、logo；青色代表行動：按鈕、建議時段（同 [`landing/`](landing/README.md#色彩分工)） |
| logo | 瑞士捲切面的螺旋（首頁改稿左上那個），正式版待畫 |

**這張提案圖上要改的地方**（首頁改稿已經改過，照搬就好，理由見 [`landing/README.md`](landing/README.md#改了什麼為什麼)）：

| 圖上現在 | 要改成 | 原因 |
| --- | --- | --- |
| 白字放在橘色上（標語、主文案） | 深咖啡字 `#5A2410` | 對比太低，手機戶外看不清楚 |
| 按鈕深藍字放在淺藍上 | 按鈕青色、字深藍 `#0B3A4A` | 同上 |
| 「幫你找出更好的出門時間」 | 「告訴我們你從哪裡來、幾點要到，幫你挑一個比較不塞的時段。」 | 我們建議的是經過那條路的時間，不是出門時間 |
| 「找到不塞的那15分鐘」 | 「每 15 分鐘一格，挑出比較順的那格」 | 會被讀成「幫你省 15 分鐘」 |
| 「準備出門」 | 「點我挑時段！」 | 同「出門時間」 |
| 只有汽車 | 加一台機車 | 議題寫「汽機車」，台北通勤族看到機車才覺得在講自己 |
| 沒有題目副標、資料標示 | 加「內科晨峰・平日 07:00–09:30」與「含模擬資料」 | 換題只換副標；資料標示規則 |

**不用再決定的：**

- 品牌風格只包在外層（首頁、封面、分享卡、簡報章節頁）；熱力圖、錯峰情境、協商一頁紙維持冷靜的數據風格，照 [`Tokens.dc.html`](heatmap-canvas/Tokens.dc.html)（底色 `#F5F4EF`、主色 `#1F4E79`、壅塞色階、藍橘發散色階、四種資料標籤、Noto Sans TC 加等寬數字）。
- 熱力圖的色階不因品牌改變。
- 文字對比至少 4.5:1（大字 3:1），色階要通過色盲模擬與黑白列印。
